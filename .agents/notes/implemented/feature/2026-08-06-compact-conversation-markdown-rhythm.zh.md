# Agent Note: 紧凑的对话 Markdown 节奏

Status: implemented

[English](2026-08-06-compact-conversation-markdown-rhythm.md) | 中文

## 问题

assistant 回复采用易读的 16/28 排版，但可复用 Markdown 基线还会为普通块设置 16px 外边距、为水平分隔线上下各设置 32px 外边距，并在大标题前留出 32px。纯文本段落仍有舒适的阅读体验；回复一旦组合标题、列表、引用、分隔线或代码区域，就会累积出过多空白，在对话中显得松散割裂。

## 决策

`MarkdownText` 保留与 deepsuite 兼容的度量值作为回退；组件本地的可继承自定义属性只表达块间节奏。`AssistantMarkdown` 提供会话取值：普通块间距为 12px，列表项间距为 4px，一级至三级标题前间距为 24px、后间距为 12px，水平分隔线上下各为 20px。其自身的多块内容间距与已结束操作区间距也都是 12px。字号、正文 28px 行高、颜色、语义元素、Markdown 源文本与交互行为保持不变。

覆盖值位于 assistant 展示根节点，因此已定稿回复、流式 assistant 文本、被中断的部分输出，以及由 assistant 持有的展开 Markdown 都使用同一套节奏。其他 `MarkdownText` 消费方不会继承会话取值，继续使用可复用原语的原始间距。1px 分隔线和所有绘制属性继续使用共享语义 token；只有以 4px 为倍数的布局值会因消费方而异。

本决策仅部分取代[安全 assistant Markdown 决策](2026-07-23-web-assistant-markdown.md)中有关默认间距的陈述。该 Agent Note 继续负责解析、不受信任输出策略、语义化渲染、排版 token 与代码块行为。

## 考虑过的替代方案

**缩小正文字号或行高。**不予采用：纯文本内容已经易读；为解决由块边界造成的问题而压缩每一行，会牺牲阅读舒适度。

**全局修改可复用 Markdown 默认值。**不予采用：Web 回答、计划审阅、Trajectory 与其他嵌入表层可能需要既有的 deepsuite 节奏。对话自行负责它所需的紧凑阅读语境，不会在没有显式声明的情况下重调所有消费方。

**为每一组相邻 Markdown 元素添加专用选择器。**不予采用：标题、列表、段落、引用、分隔线、表格与代码的组合会形成一个不断扩张的选择器矩阵。一套可继承的节奏值会保持语义 DOM 不变，并让常规外边距折叠处理相邻块。

## 后果

混合格式回复会占用更少的纵向空间，并保持更清晰的章节连续性，尤其是在水平分隔线附近；纯文本段落则保留既有字号与行高。对话显式负责自身的内容密度；共享原语增加一个小型可继承样式 seam，但不增加 React prop 或运行时依赖。设置这些自定义属性的消费方可以修改间距，因此回退值仍会定义可复用的默认值。

## 测试

Markdown 组件测试套件继续固定语义化 GFM、TeX、安全与代码块行为。GUI 与组装后的 Web 测试套件覆盖未改变的渲染路径。浏览器验证在生产视口下检查段落／分隔线／引用内容，以及另一段包含标题／列表／表格的历史记录；测得的混合格式样例高度从 474px 收紧至 410px，同时文本与 28px 行高保持不变。
