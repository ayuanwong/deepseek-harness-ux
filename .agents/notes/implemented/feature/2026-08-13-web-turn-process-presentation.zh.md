# Agent Note: Web 轮次过程展示

[English](2026-08-13-web-turn-process-presentation.md) | 中文

Status: implemented

## 问题

对话流曾把推理、上下文、中间 Assistant 说明和 Tool 行作为同等的记录项渲染。任务运行时，一个工作因此被拆成多个游离区块，原始 `Think` 文案直接暴露，最终答案前还会出现巨大空白。若在轮次仍运行时把这些内容全部折叠，又会移除用户确认任务仍在推进所需的反馈。提问前的说明还可能先以游离正文出现，随后跳入过程容器，但用户恰恰需要阅读这段解释才能回答问题。

## 决定

ChatView 在现有稳定 keyed Conversation Nodes 之上增加一层仅用于展示的轮次分组。运行中的轮次在最终答案前只拥有一个稳定且展开的 `ProcessPanel`。面板保留 `Deep diving...` 标识、步骤数、耗时与紧凑语义活动轨迹。安全的任务对象分类会即时提供一个非空标题且不复述用户请求；一次有界辅助调用则可以把新记录的 Todo、流式推理与 Tool 活动提炼成具体标签。答案正文会被刻意排除，避免流式正文、约束项或字段标签被误当成阶段。客户端会把连续流节流为粗粒度活动版本，再只接受对当前阶段的原位改写，或追加一个更后的阶段，因此重复出现的旧文案不能再成为当前阶段。即便辅助响应误报为追加，前缀逐步增长的文案也会被强制原位替换。显式 Todo 和模型撰写的 Tool 说明可以立即推进本地标题；原始流式推理在精炼前不再成为可见标题，因为其最新句子常尚未完整且会被替换。通用状态文案、用户问题复述、命令、路径、单独的 Tool 名称、第一人称叙述和答案元数据都不能成为标题。原始上下文、推理、命令和 Tool renderer 仍可在内层默认折叠的“运行详情”中查看。

可见的 Assistant 正文先进入阶段下方一个稳定的候选答案位置，而不是塞进蓝色阶段轨道。若后续出现 Tool 或交互活动，同一个位置会原位升级为带标签的阶段结果，不会先作为游离正文出现，再跳进另一个容器。这样既能在问题或审批接管输入区时保留提问前解释，又不会把正在生成的最终答案误判成中间结果。运行中调用切换为已结算节点时，仍沿用同一个 keyed 过程父节点；所有曾被观察为打开状态的轮次都会保留折叠后的过程摘要，包括详情 Node 在收尾答案到达前已经结算消失的第二轮及后续轮次。Host running 位负责即时运行态展示，只有仍在等待的问题或审批会延长这个状态。会话空闲且没有待处理交互时，即使 `turn/end` 因另一条事件通道而延迟，外层过程也会结算并折叠；运行时会在后台刷新持久化尾部，而最后一条已结算 Assistant 会暂时占据收尾答案位，直到该边界到达。已恢复的中途 Tool 或命令错误仍可在“运行详情”中检查，但不会把已结算过程变成警告；终止轮次的错误或未恢复失败仍保持展开。只有一行答案、从未被观察为运行中且没有任何辅助活动的已完成轮次不会生成空的过程展开项。

同一辅助服务还可以只在浏览器渲染层替换已完成收尾 Assistant 消息的标题。它解析 Markdown 偏移，在 `turn/end` 后发送有界的标题与段落记录，并保留原始内容块作为复制、branch、回放与模型历史的数据源。

每份辅助输入都从现有 Session 日志重建，并在调用前记录为 `web/presentation-llm-request`。该事件只存在于日志，因此 `deriveMessages()` 不变。调用使用 `purpose: 'presentation'`、不获得工具、受 token 与时间上限约束，并关闭 DeepSeek 思考。它绝不改变 Agent System Prompt、请求标头、消息、Tool 执行或收尾答案；失败时保留原始展示。

## 备选方案

**向 Agent System Prompt 注入展示指导。** 否决，因为它会改变模型输入，并可能改变原本只应被添加标签的答案。

**只使用本地字符串启发式。** 不作为唯一来源，因为它无法稳定地命名任务特定阶段，也无法改善修辞化的答案标题。它仍作为零延迟回退。

**运行时永久展示所有原始行。** 否决，因为技术活动会与语义阶段争夺注意力，并重新制造碎片化布局。

**运行时折叠整个过程。** 否决，因为结果出现前会失去进度反馈。轮次运行时只折叠技术详情。

## 结果

运行中的工作成为一个安静、向前推进、可理解且可按需检查详情的过程；完成后，注意力回到答案，同时过程历史仍可检查。浏览器回放固定了等待提问这一边界：解释在运行中的阶段结果里只出现一次，外层过程直到交互与任务都结算前保持展开，此后在最终答案旁折叠。组件测试还固定 Tool 生命周期更新前后的同一个 DOM 父节点、第二轮结算后保留折叠过程、区分已恢复 Tool 失败与终态错误、在 idle 早于 `turn/end` 到达时停止运行态展示、拒绝旧语义语句再次成为当前步骤，并证明标题替换不会改变原始 Markdown。运行时测试会在 idle 边沿尾部刷新修复持久化轮次边界时保留已加载的更早分页。

展示调用会增加有界的提供方用量，也可能在底层内容已经可见之后才完成。它们不阻塞主任务，且失败时安全回退，但部署方仍需支付这项可选展示成本。精确请求会持久保留以便审计；结果是短暂的，重启后可以重新计算。

本文只取代[将 Web 队列消息转入当前轮次](2026-07-30-web-queue-steer-action.md)中的 transcript 展示位置描述：待处理 steering 现在跟随稳定的轮次过程分组，而不是独立的运行状态行。原文仍是 Queue、steering 和生命周期语义的权威说明。
